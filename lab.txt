expt  9: Installation of OpenStack and VM Creation

1. Check system readiness


lsb_release -a
uname -m
nproc
free -h
df -h /
sudo apt update
sudo apt install -y snapd cpu-checker
sudo systemctl enable --now snapd
sudo kvm-ok


**Prerequisite:** Use an Ubuntu x86_64 VM with sufficient RAM, disk space and working KVM/nested virtualization. Stop if KVM is unavailable.

2. Install MicroStack


sudo snap install microstack --beta
snap list microstack


 3. Initialize OpenStack


sudo microstack init --auto --control
 **note the dashboard url

Wait for initialization to finish successfully.

 4. Verify installation and resources


microstack.openstack --version
sudo snap get microstack config.credentials.keystone-password
microstack.openstack image list
microstack.openstack flavor list
microstack.openstack network list


Confirm that a usable image, the `m1.tiny` flavor, and a usable network are present before creating the VM.

5. Create the virtual machine


microstack launch cirros --name vm1


Wait for the command to finish.

6. Verify VM creation


microstack.openstack server list
microstack.openstack server show vm1


**Expected result:** The VM named `vm1` reaches `ACTIVE`.

 7. Dashboard access


ip -br addr
sudo snap get microstack config.credentials.keystone-password


Use the dashboard URL printed during initialization.if not(sudo snap services microstack)

**Login**
- Username: `admin`
- Password: The value printed by the Keystone password command.

**Result:** OpenStack installed, resources verified, and a CirrOS virtual machine created.


expt 10
PART A — CREATE VHD ON WINDOWS

1. Press Win + R -> type diskmgmt.msc.
2. Disk Management -> Action -> Create VHD.
3. Choose location, size (e.g., 2 GB), VHD/VHDX, and Dynamically expanding -> OK.
4. Right-click the new disk -> Initialize Disk.
5. Right-click Unallocated space -> New Simple Volume -> assign drive letter -> format NTFS.
6. To move it: right-click the VHD disk label -> Detach VHD.
7. Copy the .vhd/.vhdx file to the second Windows host.
8. On the second host: diskmgmt.msc -> Action -> Attach VHD -> select file.
9. Assign a drive letter if needed and verify the files.

PART B — STORAGE VIRTUALIZATION USING LVM

1. VirtualBox -> VM Settings -> Storage -> Add Hard Disk -> Create.
2. Choose VDI -> Dynamically allocated -> 7 GB -> Finish.
3. Start Ubuntu and inspect disks/LVM:

sudo -i
lsblk
pvs
vgs
lvs

4. Identify the new empty disk by size. The example below assumes /dev/sdb.
   DO NOT use /dev/sdb unless you have confirmed it is the new disk.

pvcreate /dev/sdb
vgextend ubuntu-vg /dev/sdb
lvextend -L +3G /dev/ubuntu-vg/root
resize2fs /dev/ubuntu-vg/root

5. Verify the result:

df -h /
lsblk
pvs
vgs
lvs
What: We add a new virtual hard disk to Ubuntu.
Why: To increase the storage space available to Ubuntu.
How: We use LVM to add 3 GB to the root storage and check whether the size has increased.
LVM: A method to increase or manage storage space easily.
PV (Physical Volume): The disk we prepare to use with LVM.
VG (Volume Group): A storage pool made by combining one or more PVs.
LV (Logical Volume): A portion of the storage pool that we assign to Ubuntu to store files.
